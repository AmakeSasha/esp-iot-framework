3 ## Overview
4 
5 The ESP IoT Framework provides a comprehensive REST API for device management and monitoring. All API endpoints are prefixed with `/_/` and support JSON format for requests and responses.
6 
7 
8 ## Map URIs
9 
10 * `/_`
11  * `/wifi`
12  * `/list.json` - [Get Wi-Fi profiles](@ref h_wifi_list_json)
13 
14 ## Base URL
15 
16 ```
17 http://<device-ip>:80/_/ # HTTP (default)
18 https://<device-ip>:443/_/ # HTTPS (if enabled)
19 ```

21 ## Authentication
22 
23 ### Basic Authentication
24 When `CONFIG_EIF_ENABLE_BASIC_AUTH` is enabled, all administrative endpoints require Basic Authentication.
25 
26 **Credentials:**
27 - Username: `admin`
28 - Password: Set via web interface or API
29 
30 **Header:**
31 ```
32 Authorization: Basic YWRtaW46cGFzc3dvcmQ=
33 ```
34 
35 **Note:** Replace `YWRtaW46cGFzc3dvcmQ=` with your base64-encoded `admin:password`

37 ## API Endpoints
38 
39 ### Wi-Fi Management
40 
41 <anchor id="h_wifi_list_json"/>
42 1. List Wi-Fi Profiles {#h_wifi_list_json}
43 
44  `GET /wifi/list.json`
45 
46  Returns all configured Wi-Fi profiles.
47 
48  **Response:**
49  ```json
50  {
51  "current_profile_index": 0,
52  "rssi_now_profile": -65,
53  "profiles": [
54  {
55  "ssid": "ESP32_SETUP",
56  "password": 12345678
57  },
58  {
59  "ssid": "OfficeWiFi"
60  },
61  {
62  "ssid": ""
63  }
64  ]
65  }
66  ```
67 
68  **Fields:**
69  - `current_profile_index`: Currently active profile (0-7)
70  - `rssi_now_profile`: RSSI of current connection in dBm
71  - `profiles`: Array of Wi-Fi profiles
72  - `ssid`: Network SSID (empty if not configured)
73  - `password`: Password (only shown for profile 0, empty for others)
74 
75 #### 2. Update Wi-Fi Profile
76 **POST** `/wifi/update.do`
77 
78 Update or create a Wi-Fi profile.
79 
80 **Request Body:**
81 ```json
82 {
83  "profile_index": 1,
84  "ssid": "MyNetwork",
85  "password": "MyPassword123"
86 }
87 ```
88 
89 **Parameters:**
90 - `profile_index`: Profile number (0-7, where 0 is system profile)
91 - `ssid`: Network SSID (1-32 characters)
92 - `password`: Network password (8-64 characters)
93 
94 **Response:** HTTP 204 No Content on success
95 
96 #### 3. Test Wi-Fi Connection
97 **POST** `/wifi/check.do`
98 
99 Test connectivity for a specific Wi-Fi profile.
100 
101 **Request Body:**
102 ```json
103 {
104  "profile_index": 1
105 }
106 ```
107 
108 **Response:** HTTP 202 Accepted (test started in background)
109 
110 **Note:** Check test results with `/wifi/status.json`
111 
112 #### 4. Get Connection Test Status
113 **POST** `/wifi/status.json`
114 
115 Get results of a Wi-Fi connection test.
116 
117 **Request Body:**
118 ```json
119 {
120  "profile_index": 1
121 }
122 ```
123 
124 **Response:**
125 ```json
126 {
127  "result": true,
128  "rssi": -72
129 }
130 ```
131 
132 **Fields:**
133 - `result`: `true` if connection successful, `false` otherwise
134 - `rssi`: Signal strength in dBm (if connected)
135 
136 #### 5. Clear Wi-Fi Profile
137 **POST** `/wifi/clear.do`
138 
139 Remove credentials from a Wi-Fi profile.
140 
141 **Request Body:**
142 ```json
143 {
144  "profile_index": 1
145 }
146 ```
147 
148 **Response:** HTTP 204 No Content on success

150 ### System Management
151 
152 #### 1. Get System Information
153 **GET** `/sys/info.json`
154 
155 Returns detailed system information.
156 
157 **Response:**
158 ```json
159 {
160  "heap_free": 123456,
161  "heap_min": 120000,
162  "largest_block": 80000,
163  "uptime": 3600,
164  "cpu_freq": 240,
165  "cores": 2,
166  "chip_model": "ESP32",
167  "chip_rev": 3,
168  "flash_size": 4,
169  "features": "WBL",
170  "reset_reason": 1,
171  "mac": "AA:BB:CC:DD:EE:FF"
172 }
173 ```
174 
175 **Fields:**
176 - `heap_free`: Current free heap in bytes
177 - `heap_min`: Minimum free heap since boot
178 - `largest_block`: Largest contiguous free memory block
179 - `uptime`: System uptime in seconds
180 - `cpu_freq`: CPU frequency in MHz
181 - `cores`: Number of CPU cores
182 - `chip_model`: ESP chip model
183 - `chip_rev`: Chip revision
184 - `flash_size`: Flash size in MB
185 - `features`: Chip features (W=Wi-Fi, B=Bluetooth, L=BLE)
186 - `reset_reason`: Last reset reason code
187 - `mac`: Device MAC address
188 
189 #### 2. Reboot System
190 **POST** `/sys/reboot.do`
191 
192 Gracefully reboot the device.
193 
194 **Response:** HTTP 202 Accepted (reboot initiated)

196 ### OTA Updates
197 
198 #### 1. Get Firmware Information
199 **GET** `/ota/info.json`
200 
201 Returns current firmware information.
202 
203 **Response:**
204 ```json
205 {
206  "project": "my_iot_project",
207  "version": "1.0.0",
208  "build_id": "a1b2c3d4e5f6...",
209  "build_date": "Jan 1 2026",
210  "build_time": "12:00:00",
211  "idf_version": "v4.4.0",
212  "compiler": "gcc 8.4.0",
213  "target": "esp32",
214  "partition": "factory",
215  "ota_status": "valid"
216 }
217 ```
218 
219 **Fields:**
220 - `project`: Project name from `idf_component.yml`
221 - `version`: Firmware version
222 - `build_id`: SHA256 of ELF file
223 - `build_date`: Build date
224 - `build_time`: Build time
225 - `idf_version`: ESP-IDF version
226 - `compiler`: Compiler version
227 - `target`: Target chip
228 - `partition`: Current running partition
229 - `ota_status`: OTA status (`new`, `pending_verify`, `valid`, `invalid`, `aborted`, `factory`)
230 
231 #### 2. Upload Firmware
232 **POST** `/ota/update.do`
233 
234 Upload new firmware binary.
235 
236 **Request:**
237 - Method: `POST`
238 - Content-Type: `application/octet-stream`
239 - Body: Raw firmware binary (.bin file)
240 
241 **Response:** HTTP 204 No Content on success, then automatic reboot
242 
243 **Note:** Only one OTA update can be in progress at a time
244 
245 #### 3. Confirm Successful Update
246 **POST** `/ota/confirm.do`
247 
248 Mark the current firmware as valid (prevents automatic rollback).
249 
250 **Response:** HTTP 202 Accepted
251 
252 #### 4. Rollback Firmware
253 **POST** `/ota/rollback.do`
254 
255 Rollback to previous firmware version.
256 
257 **Response:** HTTP 202 Accepted (rollback and reboot initiated)

306 ## HTTP Status Codes
307 
308 - `200 OK` - Successful GET request
309 - `202 Accepted` - Action accepted and processing
310 - `204 No Content` - Successful POST/PUT/DELETE
311 - `304 Not Modified` - Cached content still valid
312 - `400 Bad Request` - Invalid request parameters
313 - `401 Unauthorized` - Authentication required/failed
314 - `404 Not Found` - Resource not found
315 - `409 Conflict` - Resource conflict (e.g., OTA already in progress)
316 - `500 Internal Server Error` - Server error
317 
318 ## Error Responses
319 
320 For error conditions (4xx, 5xx), the response may include:
321 
322 1. **Static HTML error pages** for web interface requests
323 2. **HTTP status only** for API requests (no body)
324 3. **Serial console logs** with detailed error information
325 
326 ## Rate Limiting
327 
328 The framework implements basic rate limiting:
329 - Maximum 4 concurrent connections (configurable)
330 - Request timeouts: 8 seconds receive, 8 seconds send (configurable)
331 - Connection: close header for API requests
332 
333 ## Caching
334 
335 ### API Responses
336 - No caching for API endpoints
337 - `Cache-Control: no-store, no-cache, must-revalidate`
338 - `Pragma: no-cache`
339 
340 ### Static Files
341 - Configurable cache duration via `CONFIG_EIF_WEB_CACHE_MAX_AGE`
342 - Default: 360 seconds (6 minutes)
343 - ETag validation for cache revalidation

345 ## Examples
346 
347 ### Using curl
348 
349 #### List Wi-Fi profiles:
350 ```bash
351 curl -u admin:password http://192.168.1.100/_/wifi/list.json
352 ```
353 
354 #### Update Wi-Fi profile:
355 ```bash
356 curl -u admin:password -X POST \
357  -H "Content-Type: application/json" \
358  -d '{"profile_index":1,"ssid":"MyNetwork","password":"MyPass123"}' \
359  http://192.168.1.100/_/wifi/update.do
360 ```
361 
362 #### Upload firmware:
363 ```bash
364 curl -u admin:password -X POST \
365  -H "Content-Type: application/octet-stream" \
366  --data-binary @firmware.bin \
367  http://192.168.1.100/_/ota/update.do
368 ```
369 
370 #### Get system info:
371 ```bash
372 curl http://192.168.1.100/_/sys/info.json
373 ```
374 
375 ### Using JavaScript (browser)
376 
377 ```javascript
378 // With authentication
379 const headers = {
380  'Authorization': 'Basic ' + btoa('admin:password'),
381  'Content-Type': 'application/json'
382 };
383 
384 // Get system info
385 fetch('/_/sys/info.json', { headers })
386  .then(response => response.json())
387  .then(data => console.log(data));
388 
389 // Update Wi-Fi
390 fetch('/_/wifi/update.do', {
391  method: 'POST',
392  headers,
393  body: JSON.stringify({
394  profile_index: 1,
395  ssid: 'MyNetwork',
396  password: 'MyPassword'
397  })
398 });
399 ```

401 ## Best Practices
402 
403 1. **Always use HTTPS** in production environments
404 2. **Implement retry logic** for temporary failures
405 3. **Validate responses** before acting on them
406 4. **Monitor response times** for performance issues
407 5. **Handle authentication errors** gracefully
408 6. **Use appropriate timeouts** for long operations (OTA updates)
